# WorkBookmark 0.2.19 · 일반 드래그 폴더 묶기와 목록 이동 개선

**배포 준비 초안입니다. 실제 입력 검증을 진행 중이며, 실사용 인수와 최종 패키지 검증·배포는 아직 완료하지 않았습니다.** 아래는 현재 후보의 변경 내용입니다. 현재 공개된 배포 파일은 [0.2.18 릴리스](https://github.com/prozac0401/BookMark/releases/tag/v0.2.18)에 있습니다.

스티커를 다른 스티커 위에 끌어 놓으면 폴더로 묶을 수 있습니다. 폴더를 펼칠 때 먼저 열려 있던 트리의 위치를 유지하고, 목록 검색 결과에서 드래그할 때 행과 스크롤이 흔들리는 동작을 줄였습니다.

- **일반 드래그로 폴더 만들기:** B를 일반 스티커 A 위에 놓으면 둘을 담는 새 폴더를 만들고, 기존 폴더 위에 놓으면 그 폴더에 넣습니다. Shift는 필요하지 않습니다. 대상의 배경색이 바뀐 것을 확인하고 놓으세요.
- **Alt로 자유 이동:** Alt를 누른 동안 자석 정렬과 폴더 묶기를 건너뜁니다. 편집 중인 스티커와 자기 자신·하위 항목은 대상에서 제외합니다. 놓는 순간 대상을 다시 확인하며, 강조하지 않은 대상에 갑자기 묶지 않습니다.
- **먼저 펼친 트리 유지:** 여러 폴더를 펼칠 때 실제 화면에 먼저 펼쳐진 최상위 트리를 우선 유지합니다. 접었다 다시 펼친 중첩 폴더의 오래된 우선순위가 주변 트리를 밀지 않도록 했습니다. 임시 이동은 저장 위치를 덮어쓰지 않습니다.
- **목록 포커스 유지:** 같은 앱의 스티커·제어창으로 이동해도 목록을 유지하고, 다른 앱으로 전환하면 숨깁니다. 메뉴·드래그 처리 중 발생한 전환은 처리가 끝난 뒤 반영합니다.
- **프로세스 메시지 초기화:** 고정된 IPC 메시지 네 종류에 소스 생성 JSON 정보를 사용합니다. 메시지 형식·최대 크기·검증 규칙과 캡처 3초 제한은 유지합니다.
- **목록 드래그 안정화:** 드래그 중 검색 응답이나 항목 수정이 도착해도 화면 행은 놓기·취소까지 유지합니다. 대상 행만 다시 그리며, 목록 가장자리에 300ms 머문 뒤 120ms마다 한 행씩 스크롤합니다. 가운데로 돌아오거나 취소하면 멈춥니다.

화면에 트리 전체를 옮길 빈자리가 부족하면 해당 트리는 기존 위치를 유지합니다. 일부 폴더를 접거나 위치를 정리해 공간을 확보하세요. 한 줄 스티커, 메모 편집, 표시·숨김 단축키, 기존 색상은 유지합니다.

## 설치와 데이터

DB v8을 유지하며 스키마 변경은 없습니다. 0.2.12 이후의 책갈피·메모·폴더 관계·설정·배치는 이어서 사용합니다. 0.2.11 이하 데이터는 기존 정책대로 백업 후 v8로 이전합니다. 구버전 복귀에는 이전 전 백업이 필요합니다. [설치 및 사용 매뉴얼](user-manual.ko.md)을 참고하세요.

배포 시 `WorkBookmark-0.2.19-win-x64.msi`와 포터블 ZIP을 제공합니다. 기존 MSI에서 업데이트할 때는 새 MSI를 사용합니다. 포터블 버전이 실행 중이면 트레이에서 정상 종료한 뒤 ZIP을 새 폴더에 풀어 실행합니다. 배포 파일은 MSI·포터블 ZIP·Source.zip·SourceSnapshot.json·MSI 검증 JSON·SHA256SUMS.txt의 6종으로 준비하며, 패키지는 미서명입니다.

## 검증과 배포 기록

사람의 직접 조작으로 일반 스티커 드래그 묶기, 폴더 펼침·접힘과 주변 위치 복구, 한글 메모 자동 저장, 검색 유지, 메모 취소, 긴 목록의 양방향 드래그 스크롤과 가운데 정지, 새 폴더 생성, 기존 폴더 넣기·꺼내기, 삭제·복원 후 폴더와 메모 보존을 확인했습니다. 기존 Computer Use 도구로 단축키 표시·숨김, 현재 후보의 합성 문서 재개·실제 메모장 캡처와 다른 앱 전환 시 목록 숨김을 확인했습니다. 재시작 뒤 한글 메모·폴더 관계도 보존했습니다. 초기 수동 입력과 현재 후보의 바이너리 지문 및 검증 범위는 [실사용 기록](evidence/acceptance-0.2.19-2026-11-04/README.md)에 구분합니다.

현재 후보의 Desktop 713개는 종료 예외 없이 통과했고, 메시지 호환성 검사를 포함한 Core 86개와 IPC 17개도 통과했습니다. 최종 소스를 고정한 뒤 전체 빌드·회귀검사와 MSI 구조 검사·관리 추출 파일 해시 대조를 수행합니다. 배포 파일의 최종 MSI 결과는 첨부 검증 JSON, 커밋과 파일 지문은 SourceSnapshot.json·SHA256SUMS.txt를 기준으로 합니다.

IPC 조사에서 실제 작업 프로세스의 최초 요청 한 번이 약 3.05초로 제한 시간을 넘었습니다. 동일 후보의 반대 순서 재측정은 6/6 통과했지만 전체는 11/12이며, 첫 실행 지연이 완전히 해결됐다고 주장하지 않습니다. 실제 합성 메모장 캡처는 1.216초에 성공했습니다. 호스트 부하·파일 캐시 영향을 분리한 성능 보장 시험은 아닙니다. [조사 기록](evidence/real-use-2026-11-04/sourcegen-investigation-summary.json)에 최초 실패와 재측정을 모두 남겼습니다.

현재 MSI 설치·업데이트·제거·재로그인 전주기, 서로 다른 배율의 다중 모니터 이동과 Office/탐색기 50회 실기 행렬은 이번 변경의 완료 범위에 포함하지 않습니다. 관리 추출은 실제 설치 시험을 대신하지 않으며, 합성 메시지·private handler 검사는 실제 포인터·키보드 입력의 성공을 뜻하지 않습니다. 한글 입력은 이번 사람의 직접 입력 결과와 구분해 기록했습니다.
