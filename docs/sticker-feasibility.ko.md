# 업무 책갈피 스티커 보기 검토

검토일: 2026-09-22 · 기준 소스: `1268431` · 상태: 구현 전 설계 검토 기록

후속 0.2.0에서 목록/스티커 선택과 독립 포스트잇 창을 구현했습니다. 최종 동작은 [릴리스 노트](release-notes-v0.2.0.md), 구현 검증은 [검증 기록](evidence/stickers-2026-09-22/README.md)을 참고하세요. 아래 내용은 초기 제안의 이력입니다.

## 판단

현재 WinForms + SQLite 구조에서 구현할 수 있다. 책갈피의 수집·Office/탐색기/브라우저 재개 기능을 재사용하면서 별도의 스티커 창과 표시 상태를 추가하는 방식이 적합하다. 이 판단은 소스 검토와 Microsoft API 문서에 근거하며, 실제 스티커 창의 Windows 동작을 검증한 결과는 아니다.

사용자가 말한 **스티커 삭제 = 목록에서 해당 책갈피 지우기**를 기본 계약으로 삼는다. 목록 전체 비우기와는 다른 동작이다. 스티커 자체에 대상 정보를 복제하지 않고 기존 `Bookmark.Id`를 연결한다. 파일, 문서, 웹페이지와 열려 있는 대상 앱에는 삭제·닫기 명령을 보내지 않는다.

## 표시 방식의 선택

| 방식 | 잘 맞는 상황 | 고려할 점 | 상대 작업량 |
|---|---|---|---|
| 책갈피마다 독립 스티커 창 | 작업 중 다음 할 일을 계속 떠올리고, 원하는 화면 위치에 두기 | 여러 창, 포커스, 모니터·배율 변경, 위치 복원이 필요 | 중간 |
| 한 창 안의 스티커 보드 | 책갈피가 많고 한눈에 훑으며 정리하기 | 보드를 열어야 보이므로 바탕화면 상주와는 경험이 다름 | 낮음~중간 |
| 전체 목록을 담은 작은 상주 창 | 공간을 적게 쓰면서 빠르게 재개하기 | 각 책갈피를 개별 위치에 붙일 수 없음 | 낮음 |

우선안은 **기존 검색 목록 + 선택한 책갈피의 독립 스티커**다. 필요할 때 목록에서 `스티커로 표시`를 선택한다. 새 책갈피를 항상 스티커로 띄우는 설정은 선택 사항으로 제공한다. 사용자 확인 전의 추천안이며, 전 항목을 스티커로 표시하는 방식도 같은 구조로 구현할 수 있다.

바탕화면에서 보이는 일반 도구 창으로 시작한다. `항상 위`는 개별 선택으로 둔다. 일반 창은 다른 앱에 가려질 수 있으므로 트레이에 `스티커 모두 보기 / 잠시 숨기기`를 제공한다. Windows 바탕화면 아이콘 계층에 직접 붙이는 방식, Win+D 예외 동작, 모든 가상 데스크톱 고정은 별도 검증 과제로 둔다.

## 사용성을 위한 동작 제안

| 사용자 동작 | 결과 |
|---|---|
| 작업 창에서 기존 저장 단축키 | 지금과 동일하게 책갈피 저장. 자동 표시 설정이 켜져 있으면 커밋 후 스티커 표시 |
| 스티커의 `이어가기` 클릭 | 저장한 문서·셀·페이지로 재개. 책갈피와 스티커는 유지 |
| 위쪽 손잡이 드래그 | 위치만 변경. 재개·삭제 동작을 실행하지 않음 |
| `메모` 선택 | 기존 한 줄 메모 편집기를 열기. 다음 행동을 짧게 적도록 유도 |
| `목록에서 지우기` 선택 | 커밋 후 스티커와 최근 목록에서 같은 항목 제거 |
| 목록에서 같은 항목 삭제 | 열린 스티커도 함께 제거 |
| `되돌리기` | 같은 ID·메모·스티커 위치·색상으로 복원 |
| `잠시 숨기기`, 창 닫기, Alt+F4 | 표시만 숨김. 명시적 삭제 명령과 분리 |
| 앱 종료·업데이트·Windows 종료 | 창 자원 해제. 책갈피 삭제 없음 |
| 같은 위치를 다시 저장 | 기존 중복 판정에 따라 같은 ID 갱신. 스티커 중복 생성 없음 |

스티커는 `프로그램 종류 → 파일명 → 저장 위치 → 다음 행동 메모 → 이어가기` 순으로 구성한다. 예를 들어 `Excel / 9월 정산.xlsx / 매출!D127 / 거래처 회신 반영 후 합계 확인`이면 목적지가 구체적으로 보인다. 메모가 없으면 파일명과 위치만으로 충분히 쓸 수 있어야 한다. 같은 파일의 다른 셀은 별도 책갈피이므로 시트·셀을 생략하지 않는다.

초기 크기는 약 260 × 180 논리 픽셀을 후보로 삼되 긴 한국어 파일명과 200% 배율에서 평가한다. 긴 경로는 부모 폴더 등 구별 가능한 부분을 표시하고 전체 경로 확인을 제공한다. 색상은 선택 사항이고 의미는 항상 글자로도 전달한다. 분류, 우선순위, 마감일 입력을 필수로 만들지 않는다.

삭제는 확인 대화상자 없이 되돌리기를 제공하는 것이 기존 흐름과 맞는다. 다만 현재의 마지막 한 건/10초 방식은 연속 삭제에 약하다. 삭제 토큰을 항목별로 관리하는 되돌리기와 앱을 다시 열어도 쓸 수 있는 `최근 삭제` 복원을 추천한다. 최근 삭제 메뉴는 기존 논리 삭제 기록을 읽는 추가 기능이며, 영구 삭제나 자동 보관 만료는 이 제안에 포함하지 않는다.

일반 창 닫기를 삭제로 연결하지 않는다. `CloseReason.UserClosing`에는 코드에 의한 닫기와 일부 작업 관리자 종료도 포함될 수 있어 삭제 의도를 판별하는 근거로 부족하다. 휴지통 버튼/`목록에서 지우기` 명령만 데이터 삭제를 요청하도록 설계한다. [Microsoft CloseReason 문서](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.closereason?view=windowsdesktop-10.0)

## 구현 구조 제안

`StickerForm`은 화면과 사용자 명령만 담당하고, `StickerManager`가 `Dictionary<Guid, StickerForm>`으로 중복 창을 막는다. 공통 명령 계층에서 기존 저장소에 쓰고, **커밋된 결과만** 목록과 스티커에 전달한다. 단축키 캡처, 브라우저 캡처, 수동 URL 저장, 메모 변경, 위치 다시 지정, 삭제, 복원, 재개 결과가 모두 이 경로를 통과한다.

열린 최근 목록은 현재의 선택 안정성 규칙을 유지한다. 새 저장 때문에 읽고 있던 행이 갑자기 재정렬되지 않게 하고, 같은 ID의 내용·삭제 상태만 갱신한다. 다음에 열 때 최신 저장 순서를 읽는다. 스티커는 같은 ID의 내용만 바꾸고 사용자가 정한 위치를 유지한다.

스티커의 표시 정보는 별도 테이블 `bookmark_sticker_layout`에 두는 안을 권한다:

```text
bookmark_id   PK, bookmarks.id 참조
desktop_enabled
monitor_device
x_dip, y_dip, width_dip, height_dip
color_key
collapsed
always_on_top
```

좌표는 저장 당시 모니터 작업 영역을 기준으로 한 96 DPI 논리 단위로 정의한다. 시작 시 현재 모니터·배율에 맞춰 변환하고 작업 영역 안으로 보정한다. 모니터가 없어졌으면 주 모니터 안으로 이동시킨다. `스티커 모두 모으기` 명령으로 배치를 복구할 수 있게 한다. 이동 완료 시 저장하여 드래그 중 DB 쓰기가 반복되지 않게 한다.

현재 DB 스키마 버전은 4다. 테이블 추가 시 버전을 올리고 기존 백업·트랜잭션 기반 마이그레이션을 확장해야 한다. 스티커 배치 저장을 못해도 이미 저장한 책갈피를 실패로 뒤집지 않고 `배치를 저장하지 못함`만 안내한다. 논리 삭제 중에는 배치 행을 남겨 되돌리기에 사용하고, 재시작 시 삭제된 책갈피의 스티커는 생성하지 않는다.

WinForms의 `TopMost`는 다른 일반 창 위에 표시하는 기능이고, `ShowWithoutActivation`은 처음 표시할 때 작업 중인 창의 입력 포커스를 유지하는 기능이다. 둘을 별개로 설계한다. 자동 표시는 비활성으로, 사용자가 메모 편집을 요청하면 입력 가능한 창으로 전환한다. [TopMost](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.form.topmost?view=windowsdesktop-10.0), [ShowWithoutActivation](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.form.showwithoutactivation?view=windowsdesktop-10.0)

화면 안으로 위치를 보정할 때 `Screen.WorkingArea`를 사용할 수 있다. 이 속성은 보통 작업 표시줄·도킹 도구 모음이 제외된 영역을 제공하지만 작업 표시줄 자동 숨김 등은 실제 환경에서 확인해야 한다. [Screen.WorkingArea](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.screen.workingarea?view=windowsdesktop-10.0)

## 권장 개발 순서

1. **기본 흐름:** 목록에서 스티커 표시, 1회 클릭 재개, 기존 메모 편집, 양방향 삭제·복원, 공통 변경 통지. 기존 캡처·재개 어댑터를 재사용한다.
2. **일상 사용 완성:** 위치·모니터·크기 복원, 모두 보기/숨기기/모으기, 연속 삭제와 최근 삭제 복원, 키보드 접근성, 한글 IME, 실패 상태 표시. 실제 배포 전 필요한 범위다.
3. **사용 후 조정:** 신규 저장 자동 표시, 접기, 제한된 색상, 항상 위. 여러 줄 메모·스티커 보드는 실제 필요가 확인되면 확장한다.

외형 제작보다 여러 창의 데이터 일관성과 입력 포커스가 주요 작업이다. 별도 UI 프레임워크로 이전할 이유는 현재 검토에서 발견하지 못했다. 소요 일수는 스티커 표시 정책과 Windows 실기 결과가 정해지기 전 확정하지 않는다.

## 구현 후 확인할 사용성·회귀 시나리오

- 스티커 삭제 시 같은 목록 항목만 사라지고 실제 파일은 유지되는가. 목록 삭제도 스티커에 반영되는가.
- A/B/C를 연속 삭제하고 각각 되돌려도 잘못된 항목을 복원하지 않는가. 다시 시작한 뒤 최근 삭제에서 복원할 수 있는가.
- DB 쓰기 실패 시 스티커가 사라지거나 성공 알림이 뜨지 않는가.
- 같은 위치 재저장 시 스티커가 하나만 유지되고 메모·배치가 보존되는가. 삭제 항목 재저장도 동일한가.
- 새 저장이 최근 20개 밖의 기존 스티커를 사라지게 하지 않는가.
- 종료·Alt+F4·업데이트·로그오프가 삭제로 해석되지 않는가.
- 스티커 자동 표시 중 Excel 입력·선택이 바뀌지 않는가. 스티커 클릭 재개가 기존 입력 감시와 충돌하지 않는가.
- 스티커 드래그, 메모 편집, 한글 조합 확정이 문서 열기를 잘못 실행하지 않는가.
- 100/150/200% 배율, 서로 다른 배율의 듀얼 모니터, 모니터 분리 후에도 스티커를 찾을 수 있는가.
- 키보드와 스크린 리더로 이어가기·삭제·복원을 사용할 수 있는가. 메모 입력 중 Delete/Ctrl+Z가 책갈피 삭제/복원으로 가로채이지 않는가.

사용성 평가는 스티커 3개·10개·30개 상황에서 `대상 찾고 재개하는 시간`, `잘못 연 횟수`, `의도치 않은 삭제와 복구 성공`, `문서 작업을 가린 정도`, `정리하는 데 든 시간`을 기존 목록과 비교한다. 처음에는 자주 쓰는 3~5개로 평가하되 제품의 강제 한도로 삼지는 않는다. 창 수가 많을 때의 메모리·응답성도 측정 후 표시 정책에 반영한다.

## 이번 검토의 범위

제품 소스와 DB를 수정하지 않았다. 대화에 제시하는 시안은 합성 예시 데이터를 이용한 삭제·복원·메모 표시 검토용이다. 실제 파일 열기, Windows 독립 창, 모니터 간 이동, OS 종료 동작을 구현하거나 검증한 것은 아니다.

시안은 로컬 Chrome에서 스티커→목록 삭제, 목록→스티커 삭제, 되돌리기, 최근 삭제 복원, 메모 수정·취소, 숨기기 시 기록 유지 동작을 확인했다. 736px/320px 너비와 밝은/어두운 테마를 확인했으며, 확인한 동작에서 JavaScript 실행 오류와 320px 가로 넘침은 없었다. 이 결과는 Windows 제품 실기 검증과 구분한다.
