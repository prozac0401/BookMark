# 웹 URL Office 문서 갈무리 · 0.1.4 시험 빌드

2026-09-21 구현. **자동검사 대상이며, 실제 회사 AD 인증·Office 연동 검증은 사용자가 진행합니다.**

## 사용 방법

1. 이 시험 빌드를 별도 폴더에 풀고, 기존 WorkBookmark를 트레이 메뉴에서 종료한 뒤 새 `WorkBookmark.exe`를 실행합니다. 기존 사용자별 로컬 DB를 계속 사용합니다.
2. 회사 인증을 마치고 **데스크톱 Excel·Word·PowerPoint**에서 웹 문서를 엽니다.
3. 기록할 셀·본문 위치·슬라이드에서 **Ctrl+Alt+B**를 누릅니다.
4. 위치를 옮긴 뒤 **Ctrl+Alt+J → 항목 선택 → Enter**로 재개합니다.
5. 닫힌 문서는 해당 Office 앱에 URL 열기를 요청합니다. 문서 준비가 확인되면 저장한 위치로 이동합니다. 로그인·로딩·새 입력 때문에 위치 이동을 확인하지 못하면 안내가 표시됩니다. **Office에서 로그인과 문서 열기를 마친 뒤 같은 책갈피를 다시 실행**하세요.

브라우저의 Word/Excel/PowerPoint 웹앱은 기존 확장의 URL·제목 저장 범위입니다. 이번 변경은 데스크톱 Office 앱이 원본 주소를 `http://` 또는 `https://`로 제공하는 문서에 적용합니다.

## 저장과 재개 범위

| 앱 | 저장하는 위치 | 재개 방식 |
|---|---|---|
| Excel | 문서 URL, 시트 이름, 단일 셀 주소 | 같은 웹 통합문서를 찾아 시트·셀 이동 |
| Word | 문서 URL, 본문 문자 오프셋 | 같은 웹 문서의 본문 위치로 이동 |
| PowerPoint | 문서 URL, SlideID, 표시용 슬라이드 번호 | SlideID로 현재 순서를 확인한 뒤 이동 |

- 현재 문서 객체에서 원본 URL과 위치를 읽습니다. 별도 HTTP 요청이나 `File.Exists`로 웹 주소의 접근 가능 여부를 검사하지 않습니다.
- 다시 열 때 `ms-excel:ofe|u|…`, `ms-word:ofe|u|…`, `ms-powerpoint:ofe|u|…`로 해당 Office 앱의 편집 모드 열기를 요청합니다. 인증과 읽기/쓰기 권한은 Windows·Office·문서 서버가 처리합니다. 기존에 열린 문서가 있으면 그 문서를 사용합니다.
- 비밀번호·쿠키를 별도로 수집하지 않습니다. URL의 쿼리·fragment는 보존하므로 **주소 자체에 포함된 토큰은 로컬 DB에도 저장**됩니다. 원본 URL을 진단 로그에 남기지 않습니다.
- Office가 반환한 한글·공백 URL은 URI 형식으로 정규화해 비교합니다. 경로의 대소문자·쿼리 순서·서로 다른 문서 주소를 임의로 합치지 않습니다. 원본 주소는 별도로 그대로 저장됩니다.
- 확장자가 없는 다운로드 주소도 Office 문서 객체에서 얻은 주소라면 저장할 수 있습니다. Office가 다시 열 수 있는 원본 문서 주소여야 하며, 브라우저용 공유/뷰어 링크를 문서 URL로 자동 변환하지 않습니다.
- 기존 DB 열/문서 종류/작업 위치와 메모를 그대로 사용하며 DB 구조 변경은 없습니다. 같은 URL·같은 위치를 다시 갈무리하면 메모가 유지됩니다.
- 웹 Office 책갈피에는 로컬 파일 선택용 ‘위치 다시 지정’을 표시하지 않습니다. 문서 주소가 바뀌면 새 주소의 문서를 열어 다시 갈무리합니다.

## 자체 실기검증 체크리스트

Excel·Word·PowerPoint 각각 아래를 확인하세요. 동일한 이름의 문서 두 개를 서로 다른 URL에 준비하면 문서 구분도 확인할 수 있습니다.

1. **인증된 열린 문서:** 위치 저장 → 다른 위치로 이동 → 재개 시 같은 문서·같은 위치인지 확인.
2. **닫힌 문서:** 저장 후 정상적으로 문서를 닫기 → 재개 → 해당 Office 앱으로 열리고 위치가 복원되는지 확인.
3. **인증 필요:** 로그인 창 또는 로딩 대기 시 거짓 성공 표시가 없는지 확인. 인증·열기를 완료한 뒤 다시 재개해 위치 확인.
4. **문서 구분:** 같은 파일명·다른 URL, 같은 URL·다른 위치가 구분되는지 확인. 이미 열린 문서를 불필요하게 중복으로 열지 않는지 확인.
5. **한글·공백·메모:** URL에 한글/공백이 있는 문서 저장, 재저장 시 메모 유지, 앱 재시작 후 목록·위치 유지 확인.
6. **권한/위치 변경:** 접근 권한 회수, 시트 삭제, Word 본문 축소, 슬라이드 삭제 시 접근/위치 이동 실패를 확인. 성공으로 표시되면 오류입니다.
7. **기존 파일 회귀:** 로컬 Excel·Word·PowerPoint 문서의 저장·재개가 계속 동작하는지 확인.

실패를 보고할 때는 앱 종류·Office 버전, 열린 문서/닫힌 문서 여부, 표시된 안내, 보호된 보기 여부를 남겨 주세요. 실제 사내 URL·토큰·문서 본문을 공유할 필요는 없습니다.

## 제한과 구현 근거

- 보호된 보기, DRM/IRM의 자동화 제한, Office 편집/로그인 모달 창에는 기존의 보수적인 거절 규칙을 적용합니다. BookMark가 보호를 해제하거나 인증창을 조작하지 않습니다.
- Office가 원본 URL 대신 임시 다운로드 파일이나 동기화된 로컬 경로만 제공하면 그 경로를 처리합니다. 원래 웹 주소를 추측하거나 임시 파일과 URL을 같은 문서로 합치지 않습니다.
- 다른 URL로의 리다이렉트, 만료된 공유 주소, 서버 주소 변경은 자동으로 따라가며 책갈피를 다시 지정하지 않습니다.
- Word 위치는 본문 문자 오프셋입니다. 문서가 편집되면 같은 의미의 문장을 보장하지 않습니다. Excel은 시트 이름·셀 좌표, PPT는 유지되는 SlideID가 필요합니다.
- 기존 파일 경로 지원 범위는 그대로입니다. Excel은 로컬/UNC, Word·PPT는 로컬 드라이브이며 UNC 전체 지원을 이번 변경으로 주장하지 않습니다.
- 원본 파일 내용을 보관하거나 미저장 편집 내용을 복원하는 기능은 포함하지 않습니다.

공식 근거: [Office URI Schemes](https://learn.microsoft.com/en-us/office/client-developer/office-uri-schemes), [Word 웹 문서 경로](https://learn.microsoft.com/en-us/office/vba/api/word.document.path).
