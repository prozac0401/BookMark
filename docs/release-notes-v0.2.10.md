# WorkBookmark 0.2.10 · 메모 읽기·편집 중 정렬 수정

전체 숨김 이전의 메모 열기 요청이 늦게 완료돼 스티커를 다시 표시하는 문제와, 편집 중 일괄 정렬 후 과거 위치 보정값이 다시 적용되는 문제를 수정했습니다. 숨김 이후 새 메모 열기는 정상 동작하며, 저장 실패 시 초안과 편집 상태를 보존합니다.

설치 파일과 검증 파일은 **[0.2.10 릴리스](https://github.com/prozac0401/BookMark/releases/tag/v0.2.10)**에서 확인하세요. 이 문서는 **2026년 10월 6일 수정 조사 단계의 기능 검증 결과**를 재사용합니다. 최종 패키지 검사나 게시 후 다운로드 검증 성공을 미리 뜻하지 않으며, 해당 결과는 배포 패키지에 동봉한 검증 JSON을 기준으로 합니다.

## 수정 사항

### 전체 숨김 이후 늦게 완료된 메모 읽기

메모 열기 요청이 DB 읽기를 기다리는 동안 전체 숨김을 실행하면, 이전 요청의 읽기 완료가 스티커를 다시 표시하거나 포커스를 가져오지 않도록 했습니다. 요청 당시와 완료 시점의 숨김 상태 변경을 확인합니다. 숨김 이후 사용자가 새로 요청한 메모 열기는 이전 읽기가 아직 대기 중이어도 처리합니다.

### 편집 중 일괄 정렬 후 위치 복원

화면 아래쪽 스티커를 편집하면서 창이 일시 확대되고 위로 보정된 뒤, 저장 실패로 편집 상태가 유지되는 흐름을 수정했습니다. 이 상태에서 일괄 정렬하면 편집 복원 위치의 기준도 새 정렬 위치로 갱신합니다. Esc로 취소하거나 저장에 성공한 뒤 최종 위치와 저장 좌표가 정렬 위치에 맞고, 편집 전 사용자 크기·접힘 상태로 돌아갑니다.

정렬이 저장을 강제하거나 초안을 버리지 않습니다. 저장 실패 시 초안과 편집 상태를 유지하고, Esc의 기존 취소 동작도 유지합니다.

## 검증 범위

기준 소스는 **v0.2.9 / e78b1af3c5d3e9b5ecdf00aefa8b40210e8747b8**입니다. 두 문제를 집중 자동검사로 먼저 재현하고 수정 전 실패·수정 후 통과를 기록했습니다. 실제 사용자 입력 재현이나 **0.2.9에서 새로 생긴 회귀인지 여부는 확정하지 않았습니다**. 상세 원인과 로그는 [집중 검증 기록](evidence/note-regressions-2026-10-06/README.md)에 있습니다.

| 검사 | 결과 |
|---|---|
| 읽기 대기 → 전체 숨김 → 읽기 완료 | 수정 전 FAIL → 수정 후 PASS, 8개 |
| 하단 편집 → 저장 실패 → 정렬 → Esc/저장 성공 | 수정 전 FAIL → 수정 후 PASS, 4흐름·28개 |
| Desktop Release 및 참조 제품 프로젝트 빌드 | PASS, 경고 0개·오류 0개 |
| 관련 스티커·메모·표시·정렬·저장·새로고침 회귀 | PASS, **246개** |
| 독립 최종 diff 검토·공백 검사 | PASS |
| 두 흐름의 실제 클릭·키 입력 | **NOT RUN** |

**246개에는 신규 36개(8개+28개)가 포함됩니다.** 별도 집중 실행 횟수를 다시 합산하지 않습니다. 코드 변경 없는 릴리스 준비에는 이 기능검사 결과를 재사용합니다. 이전 [0.2.9의 746개 통과](evidence/sticker-alignment-2026-10-06/README.md)는 변경하지 않은 범위의 과거 근거로 보존하며 이번 실행 결과에 합산하지 않습니다. 이번 수정 조사에서는 전체 검사 파이프라인을 반복 실행하지 않았습니다.

읽기 완료 순서는 명시적 gate로 제어했으며, 임의 대기 시간으로 경쟁 순서를 만들지 않았습니다. 자동검사는 실제 WinForms 객체·메시지 루프·격리 SQLite를 사용하지만, 메서드 호출·합성 키 처리·실패 주입으로 제어한 검사입니다.

격리된 실제 앱을 실행했으나 UI 도구가 스티커 ToolWindow를 조작 대상으로 반환하지 않아 제목 클릭·Ctrl+E·Esc/Enter·트레이 정렬을 진행하지 못했습니다. 따라서 **두 흐름의 실제 UI 수용시험은 NOT RUN**입니다. 실제 설치·업데이트, 드래그·Alt 드래그, 혼합 DPI·한글 IME도 이번에 **NOT RUN**입니다. EXE 기동·MSI 구조·해시 확인은 두 흐름의 실제 UI 검증을 대신하지 않습니다. 실제 UI 수용 확인과 최초 발생 버전 판정은 남아 있습니다.

## 데이터와 설정 호환성

**DB v5, 설정 파일 버전 1, 스티커 표시 규칙 버전 3을 유지합니다.** 0.2.0~0.2.9에서 업데이트할 때 새 DB 스키마 이전은 없습니다. 이번 수정은 새 기능이나 설정을 추가하지 않으며, 기존 메모 자동 저장·사용자 크기·접힘 상태·표시 모드·단축키와 0.2.9의 토글·자석 정렬·일괄 정렬 동작을 유지합니다.

0.2.4의 사용자 지정 MSI 설치 경로 보존 수정도 포함합니다. 0.2.3 이하의 사용자 지정 설치 경로 이행은 [기존 MSI 안내](windows-installer.ko.md)를 따르세요. 0.1.7은 DB v5를 읽을 수 없으므로 구버전 복귀에는 업그레이드 전 백업이 필요합니다. [백업·업데이트 안내](user-manual.ko.md#maintenance)를 참고하세요.

## 배포 파일과 최종 패키지 확인

[0.2.10 릴리스](https://github.com/prozac0401/BookMark/releases/tag/v0.2.10)의 파일 구성은 기존과 같은 **6종**입니다.

1. `WorkBookmark-0.2.10-win-x64.msi`
2. `WorkBookmark-0.2.10-win-x64.zip`
3. `Source.zip`
4. `SourceSnapshot.json`
5. `WorkBookmark-0.2.10-win-x64.validation.json`
6. `SHA256SUMS.txt`

최종 패키지의 검사 결과·검사 수는 `WorkBookmark-0.2.10-win-x64.validation.json`, 소스 기준과 포함 방식은 `SourceSnapshot.json`, 파일 해시는 `SHA256SUMS.txt`에 기록합니다. 직접 빌드한 파일은 `artifacts/releases/<빌드시각>/`에 생성됩니다. 패키지는 서명되지 않았습니다. 패키지 검사는 실제 설치·업데이트 시험과 구분합니다.
