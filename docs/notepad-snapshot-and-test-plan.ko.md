# 메모장 자동 보관 및 테스트 분담 — 0.1.3

2026-09-19 사용자 요구: 새 메모장 문서는 사용자가 저장 위치나 파일명을 정하지 않아도 책갈피로 남기고 복원할 수 있어야 합니다. 이 요구가 이전 파일 선택 방식과 본문 미보관 계약보다 우선합니다.

## 사용 방법

1. 메모장의 새 탭 또는 기존 문서에서 작업합니다. 미저장 상태와 빈 새 탭도 대상입니다.
2. Ctrl+Alt+B를 누릅니다. 파일 선택·다른 이름으로 저장 단계 없이 당시 본문과 커서/선택 범위를 로컬 DB에 함께 기록합니다.
3. Ctrl+Alt+J에서 기록을 선택하고 Enter를 누릅니다. 저장 당시 내용으로 별도의 메모장 복원본을 열고 확인된 위치를 선택합니다.

기존 파일과 원래 메모장 탭을 저장·수정·닫지 않습니다. 기록 이후 편집은 이전 보관본을 변경하지 않습니다. 같은 제목·내용·선택 위치를 다시 기록하면 기존 메모를 유지하며 갱신하고, 내용 또는 선택이 다르면 별도 책갈피로 남깁니다. 메모장 탭 하나의 편집 이력을 자동으로 추적하는 기능은 아닙니다.

## 보관과 복원

- 본문·제목·선택 범위는 사용자별 %LOCALAPPDATA%/WorkBookmark/bookmarks.db에 보관합니다. 문서 본문은 진단 로그나 외부로 전송하지 않습니다.
- 복원 시 %LOCALAPPDATA%/WorkBookmark/NotepadRecovery 아래에 고유한 UTF-8 작업 사본을 자동으로 만듭니다. 사용자가 경로를 정할 필요가 없습니다. 재개마다 별도 사본을 사용해 이전 복원본의 편집을 덮어쓰지 않습니다.
- 사용자가 복원본을 계속 편집할 수 있으므로 작업 사본을 임의 정리하지 않습니다. DB 백업에는 메모장 보관 본문도 포함됩니다.
- 본문은 최대 2Mi UTF-16 문자이며 줄바꿈은 LF로 정규화합니다. 커서와 선택 범위도 같은 문자 좌표를 사용합니다. 지원하지 않는 문자 데이터나 제한을 넘은 본문은 거절합니다.
- 안정된 전경 편집기를 두 번 읽고 비교합니다. 캡처 중 탭·본문·선택이 바뀌면 저장을 거절합니다. SQLite 트랜잭션이 커밋되기 전에는 성공을 알리지 않습니다.
- 새로 만든 복원본의 고유 파일명, 본문, 선택 위치를 확인했을 때만 위치 복원을 성공으로 표시합니다. 지연·입력 변화로 결과를 확인하지 못하면 확인 불가로 안내하며 자동 재시도하지 않습니다.
- 기존 버전의 파일 경로형 메모장 책갈피는 파일 열기 요청 방식으로 계속 사용할 수 있습니다. 새 본문 보관본에는 파일 경로 재지정을 제공하지 않습니다.
- DB 스키마 1·2·3에서 4로 이관할 때 일관된 백업을 남기고 모든 기존 기록·메모·순서·삭제 상태를 유지합니다. 실패 시 트랜잭션을 롤백합니다.

## 추가 전체 흐름 자동시험

추가 자동화 대상은 6묶음입니다. 새 문서 저장·복원 전체 흐름, 기존 파일의 미저장 내용과 여러 탭, Chrome, Edge, 탐색기 실제 활성 탭, 한국어 IME입니다. 사용자가 직접 실행해야만 하는 항목으로 분류하지 않습니다. 실제 자동화 시도는 도구의 화면 조회·URL 확인·연결 문제로 중단됐으며, 6건 모두 제품의 성공·실패 판정이 남아 있습니다.

정책·저장소·IPC·폼 동작·단축키 등록·브라우저 호스트와 DB 연결·확장 로직은 자동시험으로 검증합니다. 실제 프로그램을 사용하는 시험과 API 대역·정책 시험의 결과를 구분합니다. 재로그인·다른 Office 비트수·네트워크/DRM·Sumatra 등 별도 환경이 필요한 시험은 일반 사용자의 필수 목록에 넣지 않고 환경별 보류로 남깁니다.

공개 배포의 검증 상태는 [0.1.3-preview.1 릴리스 노트](release-notes-v0.1.3-preview.1.md)를 참고합니다. 상세 재현 경로와 재시도 이력은 로컬 결과 엑셀에 보존합니다.
