# 문서 열기·입력 지연 수정

- 책갈피 실행 후 다른 창을 클릭해도 최초 문서 열기와 읽기 전용 열림 확인은 계속합니다. 이후 위치 이동, 강제 포커스 전환, 자동 재시도는 새 입력이 있으면 중단합니다.
- 실제 문서 열림, 저장 위치 확인, 창 활성화 결과를 구분합니다. 창을 옮겼다는 이유로 이미 확인한 결과를 잃지 않습니다.
- `처리 결과를 확인하지 못했습니다…` 팝업은 표시하지 않습니다. 확인되지 않은 결과는 성공으로 바꾸지 않고 실행 이력에 남깁니다. 실제 접근 실패 안내는 유지합니다.
- 마우스·키보드 감시는 별도 메시지 루프에서 처리하며, Office 응답을 기다리는 worker에는 저수준 입력 훅을 설치하지 않습니다. 웹 Office는 최대 45초의 확인 한도를 유지하지만 이 시간 동안 다른 작업을 할 수 있습니다.
- Office 전체 문서 조회 주기는 처음 2초 동안 250ms, 그 후 500ms로 조정합니다.

회귀 검증은 로컬·웹 Excel/Word/PowerPoint 결과 분류, 입력 감시 스레드 분리, 입력 신호 전달, 알림 억제, 캡처 취소 보호를 포함합니다. 실제 사내 웹 문서의 로그인·DRM·서버 지연은 자동시험으로 재현하지 않습니다.

2026-09-22 검증: .NET SDK 10.0.401 Release 빌드 경고·오류 0개. Core/저장소 44개, IPC 17개, Desktop 79개(입력 감시 14개 포함), Office URL/재개 103개, Shell 10개, 메모장 28개, PDF 28개로 총 309개 검사 통과. 기존 검사 프로세스와 파일 잠금을 피하기 위해 `--artifacts-path artifacts/resume-input-fix`로 빌드했습니다.

수동 확인: 닫힌 문서를 책갈피로 연 직후 다른 창을 클릭하고 문서가 열리는지 확인합니다. 웹 Office가 로그인이나 문서 준비를 기다리는 동안 마우스를 이동·클릭·스크롤해 입력 지연이 없는지 확인합니다. 새 입력 없이 실행한 경우에는 저장한 셀·본문 위치·슬라이드가 복원되는지 확인합니다.
