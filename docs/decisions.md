## 2026-09-22 스티커 수정 후보 0.2.1

사용자의 네 가지 불편과 포스트잇 모드 최상단 표시 요청을 [수정 요구사항·검증 기록](sticker-fixes-v0.2.1.ko.md)에 연결합니다. 공개 0.2.0과 로컬 수정 후보를 구분합니다.

| 결정 | 근거와 사용자 영향 |
|---|---|
| 스티커 모드에서 항상 위에 표시 | 단축키를 눌러야만 스티커를 찾을 수 있다는 피드백과 최상단 표시 요청에 따른 변경입니다. 이전 비고정 배치도 적용하며 고정 토글을 제거합니다. 위치·크기·접기와 명시적인 숨김은 유지하고 DB v5는 변경하지 않습니다. |
| 외부 작업 진행 표시는 선택한 책갈피에 한정 | 기존 단일 worker 작업 제한은 유지하면서 다른 스티커의 버튼 문구·활성 상태가 함께 바뀌는 문제를 수정합니다. 캡처에는 진행 표시할 원본 스티커가 없습니다. |
| 스티커 모드 메모는 같은 창에서 명시적으로 저장 | 별도 화면 구석으로 이동하지 않고 입력하며, 저장 실패 시 초안을 유지합니다. 목록 모드의 기존 메모 창은 유지합니다. 읽기·저장 완료가 지연돼도 더 최신 책갈피 갱신을 덮어쓰지 않게 합니다. |
| 파일 종류 아이콘은 확장자 기반 비동기 Shell 조회 | 실제 업무 파일을 읽지 않습니다. 즉시 기본 아이콘을 표시하고 최대 250ms 기다린 뒤 기본 아이콘을 유지할 수 있습니다. 네이티브 조회는 한 번에 하나, 캐시는 최대 128종이며 오래된 응답과 이미지 자원을 폐기합니다. |

## 2026-09-22 메모 영역 클릭 편집 0.2.2

사용자 요청에 따라 스티커의 별도 메모 추가·편집 링크를 없애고, 메모 본문이나 빈 안내 영역을 왼쪽 한 번 클릭하면 같은 스티커에서 입력하도록 변경했습니다. Ctrl+E는 유지합니다. 우클릭과 스크롤 조작은 편집 요청으로 처리하지 않으며, 저장·취소 후 메모 영역에 포커스를 돌려도 자동으로 다시 편집하지 않습니다. 저장 방식과 DB v5는 변경하지 않습니다. [변경 및 검증 범위](release-notes-v0.2.2.md)를 따릅니다.

## 2026-09-22 스티커 창을 벗어나면 메모 자동 저장 0.2.3

사용자가 스티커 메모를 편집하다 다른 창으로 이동할 때 자동으로 저장하고 저장 버튼을 없애 달라고 요청했습니다. 이 결정은 위 0.2.1의 **스티커 모드 메모는 같은 창에서 명시적으로 저장**한다는 선택을 대체하며, 초기 명세 3.4의 편집창 외부 클릭 저장 흐름을 스티커에도 적용합니다. 메모 영역 클릭과 Ctrl+E로 편집을 시작하는 0.2.2의 동작은 유지합니다.

| 결정 | 근거와 사용자 영향 |
|---|---|
| 다른 창이나 다른 스티커로 이동할 때 자동 저장 | 글을 입력한 뒤 작업 창으로 돌아가는 흐름에서 별도 저장 조작을 없앱니다. 저장 버튼을 제거하며 Enter / Ctrl+Enter로 즉시 저장하는 키는 유지합니다. |
| 저장 시작 전 취소 / Esc는 편집 취소 | 자동 저장되기 전에 초안을 버리는 방법을 남깁니다. 한글 조합 확정 키가 저장이나 취소로 중복 처리되지 않게 합니다. |
| 입력 조합과 스티커 내부 조작은 편집 유지 | 창 비활성화 이후 포커스·IME 처리를 기다린 뒤 저장합니다. 같은 스티커 안의 컨트롤 이동과 자체 메뉴 열기는 창 전환 저장으로 처리하지 않습니다. 저장이 시작되기 전에 다시 돌아오면 편집을 이어 갑니다. |
| 저장 실패 시 초안과 오류 안내 유지 | DB 커밋이 실패한 값을 저장된 내용으로 표시하지 않습니다. Enter 또는 다음 창 전환에서 다시 저장할 수 있게 하며, 저장 중 중복 요청을 막습니다. |
| 자동 저장 완료 후 이동한 창의 포커스 유지 | 비동기 완료나 오류 표시가 사용자를 이전 스티커로 되돌리지 않게 합니다. |
| DB v5와 목록 모드 메모 창 유지 | 저장되는 값은 기존 한 줄 최대 500자 메모이며 새 스키마 이전이나 업무 원본 변경은 없습니다. |

## 2026-09-27 사용자 지정 설치 경로 보존 · 0.2.4 후보

0.2.3 공개 MSI의 사용자 지정 경로 실기에서 복구가 기본 경로에 파일을 다시 설치하고 제거가 원래 경로에 파일을 남기는 문제가 확인됐습니다. 원래 명세의 사용자별 설치·데이터 보존 범위에서 설치 경로를 명시적으로 유지합니다.

- 설치한 경로를 제품 소유 HKCU Installer 키의 별도 component에 기록합니다. AppSearch로 읽고 UI/실행 시퀀스 모두 CostInitialize 전에 INSTALLFOLDER를 복원합니다. 관리자 권한이나 전역 설정은 추가하지 않습니다.
- 기록이 있으면 유지 관리·업데이트 명령의 다른 경로보다 원래 경로를 우선합니다. 경로 변경은 제거 후 신규 설치로만 수행하여 두 위치에 payload가 갈라지는 상황을 막습니다.
- 과거 MSI의 제거 동작은 수정되지 않습니다. 0.2.3 이전의 사용자 지정 경로는 원래 MSI와 경로를 명시한 제거 후 새로 설치합니다. 기본 경로의 기존 설치는 자동 업데이트합니다.
- 데이터 폴더·DB v5·스티커 UI와 업무 파일은 변경하지 않습니다. 제거는 MSI 소유 파일만 대상으로 하고 설치 폴더에 추가된 다른 파일은 보존합니다.
- 제품 버전을 0.2.4로 올려 기존 0.2.3 MSI와 구분합니다. 공개 배포는 별도이며 서명 없는 로컬 후보의 검증 결과를 상용 승인으로 표현하지 않습니다.

[설치 및 이전 절차](windows-installer.ko.md#024-후보-사용자-지정-설치-경로), [RegistrySearch](https://docs.firegiant.com/wix/schema/wxs/registrysearch/), [Windows Installer AppSearch](https://learn.microsoft.com/en-us/windows/win32/msi/searching-for-existing-applications-files-registry-entries-or--ini-file-entries)를 참고합니다.

## 2026-11-06 폴더 공통 패널과 명령 단위 실행 취소 · 0.2.20 구현·검증 기록

하위 스티커의 자유 이동이 트리 경계와 주변 스티커 이동을 예측하기 어렵게 만든다는 사용자 검토를 반영합니다. 아래 변경은 현재 소스의 구현 결정이며, 공개 0.2.19 MSI와 당시 검증 기록에는 소급 적용하지 않습니다.

- 트리의 위치·폭은 루트에서 조절하고 하위 항목은 부모와 형제 순서로 배치합니다. 불투명한 공통 패널을 화면 안에 제한하고 넘치는 행은 스크롤합니다. 펼침·편집으로 주변 트리를 밀지 않으며 가려진 항목으로 드롭이 통과하지 않습니다.
- 드래그는 미리보기 후 한 명령으로 저장합니다. 삽입선은 순서·소속 변경, 폴더 중앙은 끝에 넣기, 일반 항목 중앙의 묶기 영역은 새 폴더 생성입니다. 묶은 폴더는 대상 자리를 이어받아 펼치고 대상→끌어온 항목 순으로 둡니다. 하위 항목의 바탕화면 드롭은 분리, 패널 여백은 취소입니다. Alt는 루트의 자석·묶기를 끄고 하위 드래그는 취소합니다.
- 숨김은 트리 전체에 적용합니다. 목록의 **스티커에서 보기**는 조상을 펼치고 해당 트리·항목을 표시합니다. **원본 이름순 / 최근 저장순 정렬**은 명시적으로 한 번 적용하며 재캡처는 수동 순서를 바꾸지 않습니다.
- 루트 편집은 기존 크기를 유지하고 하위 편집 행만 96-DPI 기준 96픽셀로 늘립니다. 접기·숨기기·삭제·이동·종료 전 편집을 저장하며 실패하면 작업을 중단합니다. 미저장 편집이 있으면 전역 실행 취소를 진행하지 않습니다.
- 현재 세션의 내용·구조·배치 변경과 생성·삭제·복원을 같은 역순 실행 취소 이력으로 관리합니다. 입력기의 Ctrl+Z는 텍스트 편집에 한정합니다. 보기 상태·자동 기록은 제외하고, 변경 필드만 역으로 적용하여 최신 실행 기록을 덮어쓰지 않습니다. 실패·취소·무변경은 이력을 만들지 않으며 재시작 시 이력은 초기화합니다.
- DB v9는 이전 전 `.bak`을 남기고 형제 순서를 추가합니다. 기존 표시 순서와 과거 개별 좌표를 포함한 배치 기록을 보존합니다. 공개 0.2.19로 복귀하려면 v9 이전 백업을 사용합니다.

현재 조작 설명은 [사용 매뉴얼](user-manual.ko.md)에 반영하며, 공개 배포판의 범위는 [0.2.19 릴리스 안내](release-notes-v0.2.19.md)에 유지합니다.

혼합 DPI 후속 검증에서는 수동 테스트 호스트가 제품과 달리 `SystemAware`로 시작하는 점을 발견했습니다. 수동 호스트를 제품과 같은 `PerMonitorV2`로 초기화하고 적용 여부를 검사하도록 수정했습니다. 이후 왼쪽 모니터 120 DPI(125%), 오른쪽 모니터 96 DPI(100%)와 한국어 입력기 설치를 확인했습니다. 모니터·창·편집기·자식 행의 DPI와 좌표, IME 조합 상태를 기록하며, 실제 드래그와 실제 한글 조합 입력은 사용자 조작 후 별도 판정합니다.

코드 점검에서는 모니터 이동·자식 분리 미리보기가 출발 화면의 최소 크기를 사용해 125%→100% 이동 시 폭이 커질 수 있는 문제를 수정했습니다. 목적지 DPI의 네이티브 테두리를 포함한 최소 폭과 고정 높이를 미리보기·저장 복원에 공통 적용합니다. 초기 복원도 과거의 큰 높이 대신 현재 고정 높이로 화면 경계를 계산하여 하단의 저장 위치를 보존합니다. DPI 이동 수정 후 Desktop 698개 검사가 통과했으며, 이는 실제 포인터 이동이나 실제 IME 입력의 통과를 의미하지 않습니다.

초기 복원을 추가 정리한 뒤 SS12 하단 위치 보존 검사는 통과했습니다. 다만 `--stickers-only`는 두 실행 모두 SV08 뒤 목록 창을 닫을 때 `ListBoxAccessibleObject.ResetListItemAccessibleObjects → ReleaseUiaProvider → WmDestroy` 내부의 `Collection was modified` 예외로 중단됐습니다(.NET WindowsDesktop 10.0.12). 이 묶음의 완료를 통과로 기록하지 않으며, 예외의 유발 원인은 아직 확정하지 않았습니다. 호출 경로와 두 실행 로그는 `artifacts/tree-panel-review/dpi-sticker-retry-reason.json`, `stickers-after-dpi-startup*.log`에 보존합니다.

IME 자동저장과 명시적 저장 대기는 기존 조합 종료 후 120ms 보호 구간을 공유하도록 보완했습니다. 대기 후 포커스·취소·편집·조합 상태를 다시 검사하고, 입력창을 읽기 전용으로 바꾸기 전에 저장할 텍스트를 확보합니다. Esc 처리는 변경하지 않았습니다. Release 빌드 경고·오류 0개, 메모 검사 45개와 숨김·접기·종료를 포함한 context policy 검사 16개가 통과했습니다. 늦은 IME 결과 반영, 중복 저장 합류, 모드 전환 전 초안 확보 및 대기 중 복귀·취소를 포함합니다. 패널 일반 검사 22개도 통과했으며, 두 수정의 실제 사용자 입력 재검증은 별도로 진행합니다(`ime-inline-after-fix.log`, `ime-context-policy-after-fix.log`, `tree-panel-after-dpi.log`).

수정본의 실제 드래그 재검증은 통과했습니다. 120 DPI 패널 342×102·자식 행 340×45, 96 DPI 복귀 패널 274×82·자식 행 272×36을 유지하고, 멈춘 뒤 놓은 세 사례에서 루트·패널 미리보기와 확정 위치가 모두 일치했습니다. C의 위치는 재검증 시작값 (104,280)으로 유지됐습니다. 기존 (80,280)에서의 변화는 앞선 편집 종료 뒤 별도 C 드래그가 기록된 결과입니다. 최상위 C의 창 전환 IME 재검증도 조합 중 전체 문구 관찰, 포커스 이탈 후 최종 결과 반영 대기, DB의 `마지막 글자 보존` 저장을 확인해 통과했습니다. 폴더 안 자식의 실제 IME 검증은 별도로 남아 있습니다(`native-dpi-ime-retest-observed.json`, `native-dpi-ime-retest-checks.json`).

폴더 안 자식의 실제 IME 검증도 통과했습니다. 실제 입력한 `자식 한글 입력`은 첫 Enter로 조합만 확정된 뒤 두 번째 Enter에 저장됐고, 이후 초안 취소에서도 이 저장값이 유지됐습니다. 형제 B로 이동할 때 `자식 자동저장 보존`의 마지막 음절까지 저장됐습니다. 편집 중 패널 높이 82→142, 종료 후 82 복원을 확인했으며 루트 (457,61)·C (104,280), 계층·순서는 유지됐습니다. 최종 편집 상태는 모두 종료됐고, 다음 작업을 시작하며 검증 앱의 정상 종료와 원본 합성 파일 보존을 확인했습니다(`native-ime-child-observed.json`, `dpi-ime-completed-exit.json`).

0.2.20 배포 준비에서 자식 스티커에 8-DIP 둥근 Region을 적용하고 카드 사이에 불투명한 배경과 8-DIP 간격을 유지했습니다. 기존 행 위치·드래그 판정·패널 정책은 유지합니다. 편집 높이와 DPI 변화 시 영역을 갱신하고 루트로 분리하면 영역을 해제하여 기존 DWM 모서리를 사용합니다. 스티커 집중검사 362개와 실제 모니터 간 DPI 패널 검사 8개가 통과했습니다. 이 수치는 서로 겹치므로 최종 전체 검사 수에 합산하지 않습니다.

앞서 두 번 중단된 목록 종료 예외는 ListBox의 UIA 자식 제공자 해제 중 재진입으로 캐시가 다시 변경될 수 있는 경로였습니다. 종료 상태를 먼저 표시하고 목록 항목을 비운 뒤 네이티브 창을 해제하며, 지연된 갱신과 Clear 중 동기 재진입도 종료 이후 목록을 채우지 못하게 했습니다. 접근성을 끄지 않고 살아 있는 목록의 자식·선택 제공자를 유지합니다. 해당 5개 회귀검사와 이후 스티커 집중검사가 모두 완료됐습니다. 자동검사는 처리되지 않은 예외가 팝업에서 멈추거나 성공 코드로 끝나지 않도록 실패 종료하게 했습니다.

최종 외형 실기에서는 둥근 자식 자체는 확인됐지만 사각형 공통 배경과 루트보다 넓어 보이는 자식을 사용자가 지적했습니다. 루트의 네이티브 외곽 274px에는 좌우 7px 비가시 테두리가 포함되며, 기존 자식 272px는 실제 루트 카드 260px보다 넓었습니다. 실제 클라이언트 폭을 공통 기준으로 삼습니다. 사용자가 이어서 **개별 둥근 스티커만 보이기 — 카드 사이와 모서리 바깥은 배경이 보임**을 명시적으로 선택했으므로, 위의 불투명한 전체 사각 패널 정책을 대체합니다. 공통 좌표·정렬·스크롤·루트 기준점은 유지하되 실제 카드와 스크롤바 영역만 표시하고, 틈과 둥근 모서리 바깥은 투명하게 표시하며 포인터 판정도 보이는 영역에 맞춥니다.
