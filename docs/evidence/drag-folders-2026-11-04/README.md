# 스티커 폴더·좌표·목록 드래그 수정 검증

2026-11-04, Windows 11 Pro 22631, 저장소에 고정한 .NET SDK 10.0.401에서 검증했습니다. 현재 작업 트리의 개발본이며 기존 0.2.18 배포 파일의 검증 결과가 아닙니다.

## 원인과 수정

- 스티커 결합: `FindDropTarget`이 Shift를 필수로 요구해 일반 드래그에는 대상 강조와 폴더 생성 요청이 없었습니다. 일반 드래그로 대상을 강조하고, 놓을 때 같은 대상인지 다시 확인한 후 저장합니다. Alt 자유 이동, 순환 관계 차단, 편집 중 대상 제외는 유지합니다.
- 폴더 펼침: 새로 열린 폴더를 최우선으로 배치하면서 임시 이동된 폴더가 원위치로 돌아가고 기존 열린 트리를 밀었습니다. 실제 화면에 펼쳐진 최상위 트리의 순서로 공간을 확보합니다. 숨겨진 중첩 폴더의 오래된 우선순위도 남기지 않습니다. 임시 이동은 저장 좌표를 덮어쓰지 않습니다.
- 목록 떨림: 모든 DragOver에서 목록 전체를 무효화하고, 마우스 이벤트마다 가장자리 스크롤을 수행했습니다. 이전·새 대상 행만 다시 그리고, 300ms 머문 뒤 120ms마다 한 행씩 스크롤합니다. 드래그 중 검색 응답·수정 결과는 데이터에 반영하되 화면 재구성은 놓기/취소까지 보류합니다.

## 자동검사 범위

- `SI23–25`: 네이티브 이동 메시지의 완료 1회, 취소, 크기 변경·프로그램 이동 구분.
- `STR22–27`, `FS15–18`: 자석 설정과 무관한 일반 드래그, Alt 우회, 강조하지 않은 대상에 대한 결합 방지, 폴더 내부 상대 배치 보존.
- `FI01/05/07/08`: 합성 네이티브 이동 메시지 → 실제 앱 이벤트 → SQLite를 통한 새 폴더 생성, 기존 폴더로 이동, 중첩 관계, 순환 차단, 저장 실패 복구. 실제 포인터 입력과는 구분합니다.
- `TA18`, `TAI35–42`: 상하좌우와 음수 모니터 원점, 이동된 폴더 열기, 재시작, 반복 열기/닫기, 중첩 폴더를 접었다 다시 여는 경우의 위치·저장 좌표 보존.
- `RT21–37`: 대상 행만 다시 그리기, 반복 마우스 이벤트에도 고정된 스크롤 속도, 가장자리 이탈·취소 시 중단, 드래그 중 검색 응답·수정·삭제 처리.

## 실제 포인터 검사와 한계

별도 합성 SQLite 저장소에서 최종 제품 DLL과 동일한 DLL을 사용하는 실기 호스트를 실행했습니다. 호스트 관찰 기록에는 스티커 3개와 제어 창이 표시되지만, Computer Use의 `sky.list_apps` / `sky.list_windows`는 최초 조회와 재조회 모두 이 창들을 반환하지 않았습니다. 도구가 반환한 조작 대상이 없어 실제 마우스 드래그는 **NOT RUN**입니다. 창 핸들을 추측하거나 제품 창 스타일을 바꿔 실기를 대체하지 않았습니다. 기록 후 이 작업에서 실행한 테스트 호스트만 종료했습니다.
