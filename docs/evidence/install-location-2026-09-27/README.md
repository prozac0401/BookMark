# 사용자 지정 설치 경로 보존 검증 · 0.2.4 후보

기록일: 2026-09-27 · 관련 백로그: Workspace T08 · 상태: 설치 경로 수정·118개 실기 체크포인트 PASS, UI 실기 별도

## 문제와 수정

공개 0.2.3의 `INSTALLFOLDER` 지정 설치는 경로를 영구 기록하지 않았다. 실제 MSI 로그에서 복구(`/fa`)가 기본 경로를 사용하여 그곳에 다시 설치하고, 제거도 기본 경로를 사용하여 원래 경로의 파일을 남기는 것을 확인했다. 기본 경로 시험의 PASS와 별개인 제품 결함이다.

0.2.4 후보는 제품 소유 HKCU 키에 설치 경로를 기록하고 UI/실행 시퀀스의 CostInitialize 전에 복원한다. 유지 관리 중 다른 경로를 전달해도 기존 위치를 우선한다. 데이터 저장소·DB v5·스티커 동작은 변경하지 않는다. [결정 기록](../../decisions.md)과 [기존 사용자 지정 설치의 이전 절차](../../windows-installer.ko.md)를 함께 갱신했다.

## 후보와 환경

- 소스 기준: 668df2a에서 분리한 작업 트리. 원본 저장소의 main과 공개 0.2.3 파일은 보존했다.
- Windows 11 x64 10.0.22631, 일반 사용자, 기존 제품·기본 폴더·바로가기·프로세스가 없는 것을 사전 확인했다.
- 후보 `WorkBookmark-0.2.4-win-x64.msi`: 75,451,327 bytes, SHA-256 `aebd7bb3844951a02b7323ffa1d1ddd16b06ff542f0bc90691de3eb1f6f370f3`.
- 비교 대상 공개 0.2.3 SHA-256: `3424a44367e7e7c1e1483d359c595dd568d2368cea48b61e83e6b63c65eca714`.
- 새 코드는 미서명 로컬 후보이며 공개 릴리스·상용 승인으로 분류하지 않는다.

## 자동검사

`scripts/build.ps1`의 기존 검사들을 순차 실행했다. 첫 실행에서 일부 새 실행 파일의 프로세스 시작이 접근 오류로 중단되어 실패 로그를 보존했다. 동일 산출물의 재시도에서 통과했고, 이미 통과한 검사 뒤의 남은 단계부터 이어갔다. 최초 WiX 버전 조회도 실패했으나 재실행에서 고정 버전 `4.0.6+73c89738`을 확인하여 MSI 생성을 완료했다. 초기 실행 오류의 원인은 확정하지 않았으며 보안 설정은 변경하지 않았다.

| Core/SQLite·확장 대상·메모장·Office URL·스티커 저장 | 52 PASS |
| IPC | 17 PASS |

기존 자동검사는 합계 600개이며 MSI 구조 검사는 별도 50개다. 합성 IME 메시지·어댑터 검사는 실제 한국어 입력기나 설치된 Office·브라우저의 실기 합격을 뜻하지 않는다. 전체 빌드는 경고·오류 0이었다.

## 실제 설치 경로 회귀

`scripts/test-install-location.ps1`가 후보 해시와 공개 구버전 해시를 고정하고 각 MSI 작업을 하나씩 실행한다. 앱을 자동 실행하지 않는 `/qn`을 사용하며 기존 DB·설정은 내용 출력 없이 파일 존재와 SHA-256만 대조한다.

후속 버전 시험에는 정확히 같은 payload와 설치 동작을 사용하는 로컬 MSI 복사본을 쓴다. 제품·패키지 식별자와 제품 버전·업그레이드 경계만 시험용 0.2.5로 바꾼다. 이는 경로를 기억하는 버전끼리의 업데이트 검증 자료이며 0.2.5 제품 릴리스가 아니다.

초기 시험 코드의 PowerShell 예약어 충돌은 설치 전에 수정했다. 후속 MSI fixture 작성에서는 MSI SQL로 Upgrade 테이블의 기본키를 직접 UPDATE하려는 오류가 발생했다. 설치본을 정상 제거하고 기본키 행의 삭제·재삽입으로 수정한 뒤 다시 실행했다. 이 시험 코드 실패를 제품 성공으로 기록하지 않는다.

최종 수명주기 결과는 **118/118 PASS**, MSI 작업 14회 모두 종료 코드 0이다.

| 실제 동작 | 확인 결과 |
|---|---|
| 사용자 지정 경로 신규 설치 | 실행 파일·시작 메뉴·기록된 경로 일치, 기본 폴더 미생성 |
| 실행 파일 삭제 후 경로 없는 복구 | 원래 경로에 실행 파일 복원, 기본 폴더 미생성 |
| 다른 경로를 명시한 복구 | 원래 경로 유지, 전달한 다른 폴더 미생성 |
| 경로 없는 후속 fixture 업데이트·복구 | 원래 경로 유지, 새 제품 등록 하나만 존재 |
| 경로 없는 제거 | 제품 파일·HKCU 설치 등록·시작 메뉴·시작프로그램 제거, 별도로 추가한 파일은 정확한 해시로 보존 |
| 공개 0.2.3 기본 설치→0.2.4→복구→제거 | 전 단계 통과, 기본 설치 폴더 제거 |
| 공개 0.2.3 사용자 지정 설치의 명시적 제거→0.2.4 신규 설치→경로 없는 제거 | 전 단계 통과, 구·신버전 설치 폴더 잔재 없음 |
| 사용자 데이터·자동 실행 선택 | 각 단계에서 파일 존재·SHA-256 및 Preferences 동일, 앱 자동 실행 없음 |

시험 설치는 제거했다. 원시 MSI·사용자 환경 진단과 초기 실패 산출물은 로컬 artifacts에만 보관하며 기존 포터블 폴더·사용자 데이터는 유지했다.

## 남은 범위

실제 한글 IME, 창 전환 자동 저장·실패 초안·스티커 위치·작업 재개 UI는 별도 검증이다. 로그인·재부팅, 추가 PC, 조직 배포 정책과 서명은 이 기록의 통과 범위에 포함하지 않는다. 0.2.3 이전 사용자 지정 설치의 자동 경로 추론은 제공하지 않으며, 기존 MSI에 원래 경로를 지정한 제거 후 새로 설치하는 절차를 사용한다.
