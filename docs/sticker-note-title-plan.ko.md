# 스티커 메모 우선·작은 기본 크기·기본 시작 모드 개선 계획

갱신: 2026-09-27 · 기준 버전: 0.2.3 · 예정 배포: 0.2.5

사용자의 추가 지시에 따라 구현·테스트 범위를 재확정한 문서다. 이전 계획의 ‘폭 유지’, ‘기존 크기 보존’, ‘작게 맞추기 메뉴’ 안을 대체한다. 제품·관련 테스트 코드 구현을 완료했고 Release 컴파일은 경고 0개·오류 0개로 통과했다. 사용자 후속 지시에 따라 자동·수동 테스트와 화면 검증은 별도 요청까지 보류했다. 패키지 생성과 공개 배포는 수행하지 않았다.

## 1. 확정할 화면 규칙

| 상태 | 기본 화면 제목 | 대상 정보 |
|---|---|---|
| 메모 있음 | 앞뒤 공백을 제외한 메모 | 원래 제목·URL·경로·파일명·문서 내부 위치는 기본 화면에서 숨김 |
| 메모 없음 또는 공백뿐 | 웹/웹 문서: URL, 폴더: 주소, 파일/Office 문서: 파일명 | 제목 하나로 표시하고 별도 주소 블록은 만들지 않음 |
| 메모장 자동 보관본 | 메모가 있으면 메모, 없으면 기존 보관 제목 | 내부 보관 ID를 일반 주소처럼 노출하지 않음 |
| 재개 실패 또는 메모 저장 실패 | 위 제목 규칙 유지 | 필요한 실패 안내를 별도 상태 영역에 표시 |

- 본문 제목, Windows 창 제목, 접힌 상태의 식별 제목에 같은 우선순위를 적용한다. DisplayName과 저장된 대상·메모 원문은 변경하지 않는다.
- ‘다음에 할 일’ 라벨과 별도 메모 본문 블록을 제거하고 제목 하나로 통합한다.
- 기본 제목은 최대 2줄로 표시하고 넘치는 부분은 생략한다. 전체 메모와 대상 정보는 툴팁·편집창·기존 복사 메뉴로 확인할 수 있다.
- 제목 클릭 또는 Ctrl+E로 메모를 편집한다. 메모가 없어 URL/파일명이 보일 때도 같은 위치에서 메모를 추가할 수 있다.
- 기존 창 전환 자동 저장, Enter 저장, Esc 취소, 실패 시 초안 보존·재시도, 최대 500자 규칙을 유지한다. 저장 후 제목·대체 표시가 즉시 갱신된다.

## 2. 폭·높이·폰트 기준

아래 수치는 96 DPI(100%) 기준이다. 구현 기준으로 적용하고 실제 렌더에서 잘림·겹침이 있으면 같은 축소 목표 안에서 여백을 조정한다.

| 항목 | 현재 | 새 기준 |
|---|---|---|
| 기본 클라이언트 크기 | 336×302 | **260×170** |
| 최소 클라이언트 크기 | 높은 최소 높이와 외곽 폭 280 제한 | **240×160** 기준으로 창 외곽 크기를 계산 |
| 주 제목 | 12pt 굵게 | **10.5pt 굵게**, 최대 2줄 |
| 일반 글자·버튼 | 10pt | **9pt** |
| 종류·보조 안내 | 9pt | **8.5pt** |
| 메모 입력 | 10.5pt | **9.5pt** |
| 종류 아이콘 | 24px | **20px** |
| 기본 바깥 여백 | 16px | **12px** |

- 내용 영역은 폭 약 23%, 높이 약 44%, 면적 약 56% 축소한다. 실제 창 외곽에는 Windows 제목줄과 테두리가 추가된다.
- 헤더·접기·더 보기와 하단 지우기·이어가기 버튼을 작은 너비에 맞춰 재배치한다. 클릭 영역과 한글 가독성은 확보한다.
- 오류·편집 상태는 내용 영역을 재배치하여 안내와 입력칸을 표시한다. 오류 문구까지 대상 정보와 함께 숨기지 않는다.
- 앱 내부 글꼴만 조정한다. Windows 제목줄 글꼴은 시스템 설정을 따른다. 기존 DPI 스케일링을 유지하며 화면 배율에 관계없이 실제 픽셀을 강제로 고정하지 않는다.

## 3. 기존 스티커 일괄 적용과 시작 모드

**새 설치와 이번 업데이트 후 첫 실행은 스티커 모드로 시작한다. 기존 스티커도 새 기본 크기로 한 번 일괄 변경한다.**

- 크기 초기화는 이번 표시 규칙을 처음 적용할 때 1회로 정의한다. 이후 사용자가 조절한 크기와 명시적으로 선택한 목록/스티커 모드는 재시작 후에도 유지한다.
- 기존 스티커의 위치·모니터·접힘 상태를 보존하고 펼쳤을 때의 폭·높이를 새 기본값으로 바꾼다. 화면 밖으로 벗어난 위치만 기존 보정 규칙을 적용한다.
- 새 스티커, 접힌 스티커의 펼침 크기, 삭제 후 복원할 스티커의 저장 배치에도 같은 기본 규격을 적용한다. 삭제된 책갈피를 이 작업 때문에 화면에 표시하지 않는다.
- 사용자가 따로 눌러야 하는 ‘작게 맞추기’ 메뉴는 이번 범위에서 제외한다.
- 스티커 모드 시작은 저장된 책갈피를 보여주는 동작이다. 책갈피의 파일이나 URL을 자동으로 열거나 이어가기를 실행하지 않는다. 책갈피가 없을 때 가짜 스티커를 만들지 않는다.

구현은 settings.json에 별도의 표시 규칙 적용 버전(예: StickerPresentationVersion)을 추가해 1회 적용 여부를 기록한다. 기존 설정 파일 버전과 DB v5 스키마는 유지한다. 기본 DisplayMode 변경만으로는 기존에 저장된 List 값이 바뀌지 않으므로 기존 설정 전환도 함께 구현한다.

적용 순서는 **기존 배치 읽기 → 크기 변경·저장 → 스티커 모드와 적용 완료 표식 저장 → 표시 활성화**다. 완료 표식은 배치 저장이 성공한 뒤 기록하며, 실패하면 완료 처리하지 않고 재실행 시 안전하게 재시도한다. 다른 설정 저장과 경쟁하지 않도록 기존 설정 직렬화 경로를 이용한다. 잘못된 설정 파일은 기존 보호 규칙대로 보존한다.

저장된 StickerLayout의 폭·높이는 창 외곽의 96-DPI 논리 단위다. 클라이언트 크기 260×170을 DB에 그대로 쓰지 않고 제목줄·테두리를 포함한 크기로 변환한다. DB에 새 필드나 테이블을 추가하지 않고 기존 GetStickerLayouts/SaveStickerLayout 경로를 사용한다.

## 5. 확정 테스트 범위

사용자의 별도 테스트 요청 후 아래 **5개 관련 검사 클래스**를 선택 실행한다. 구현 단계에서는 테스트 코드를 준비하고 컴파일만 확인한다. 기존 fixture를 재사용하며 변경과 무관한 전체 Desktop 검사로 확대하지 않는다.

| 검사 클래스 | 필수 확인 |
|---|---|
| StickerFormChecks | 메모/빈 문자열/공백의 제목 선택, 대상 정보 중복 제거, 최대 2줄·전체 내용 확인, 작은 기본/최소 크기에서 글자·버튼 겹침 없음, 오류 안내, 접기/펼치기, 기존 명령 대상 유지 |
| StickerInlineNoteChecks | 제목 클릭·Ctrl+E 편집, 추가/수정/삭제 후 제목 갱신, 자동 저장·Enter·Esc, 실패 초안 보존·재시도, 편집·오류 상태의 작은 크기 배치 |
| SettingsDisplayChecks | 신규 기본값 Stickers, DisplayMode/적용 표식 없는 옛 설정 및 명시 List 설정 전환, 적용 이후 명시 List 선택 유지, 단축키·시작프로그램 등 다른 설정 보존, 잘못된 설정 원본 보호 |
| StickerStartupChecks | 첫 실행·업데이트 첫 시작에 단축키 없이 스티커 표시, 기존/접힘/삭제 항목의 크기 적용과 위치 유지, 빈 DB에서 불필요한 창 없음, 시작만으로 대상 파일/URL을 열지 않음, 두 번째 실행에서 초기화 반복 없음 |
| StickerPersistenceChecks | 새 기본 크기의 저장·재시작 복원, 이후 사용자 크기 변경 보존, 배치 또는 설정 저장 실패 시 완료 표식 미기록·재시도, 기존 저장 중 갱신/종료 회귀 |

- 배치 전환은 관련 시작 검사에서 실제 임시 SQLite DB로 확인하고, 저장 실패는 합성 콜백으로 주입한다. 별도의 전체 DB/Storage 검사군은 재실행하지 않는다.
- Program.cs의 기존 --stickers-only를 위 5개 클래스에 한정한 검사 묶음으로 확장한다. 자동 저장·시작 검사가 필요한 WinForms 메시지 루프와 결과/실패 종료 코드를 유지한다.
- 기존 --render-stickers로 기본·빈 메모·긴 제목·최소 크기·접힘·편집·저장 실패 화면을 확인한다. 웹·폴더·파일 대체 제목을 포함한다.
- 화면 검증은 **100%와 150%** 배율로 한정한다. 기본/최소 크기에서 글자 잘림, 버튼 클릭 영역, 오류 안내를 확인한다. 여러 모니터·전체 배율 조합의 반복 실기는 추가하지 않는다.
- 실제 입력은 제목 클릭 → 한글 메모 수정 → 다른 창으로 이동 → 제목 갱신, 재시작 → 크기/모드 유지 흐름을 한 번 확인한다. 합성 검증과 실제 입력 확인 결과는 구분한다.
- 독립적인 Office·브라우저·IPC·캡처·설치/제거/재부팅 반복 시험은 추가하지 않는다. 필수 검사 통과 후 코드 변경·새 실패 근거 없이 재실행하지 않는다.

예정 명령(실행기 수정을 완료한 뒤 사용):

~~~powershell
& .\.tools\dotnet\dotnet.exe restore tests/WorkBookmark.Desktop.Tests --locked-mode --configfile NuGet.Config
& .\.tools\dotnet\dotnet.exe build tests/WorkBookmark.Desktop.Tests -c Release --no-restore
& .\.tools\dotnet\dotnet.exe run --project tests/WorkBookmark.Desktop.Tests -c Release --no-build -- --stickers-only
& .\.tools\dotnet\dotnet.exe run --project tests/WorkBookmark.Desktop.Tests -c Release --no-build -- --render-stickers artifacts/sticker-ui-review
~~~

복원이 이미 유효하면 첫 restore는 생략한다. 현재 --stickers-only는 StickerFormChecks만 실행하므로 위 확장 전에는 충분한 검증이 아니다.

## 6. 배포 계획 유지

1. 화면·기본 설정·기존 배치 적용과 관련 테스트를 구현하고 버전·안내 문서를 함께 준비한다.
2. 위 필수 검증과 화면 확인을 1회 수행하고 docs/evidence에 실제 결과를 기록한다.
3. 같은 소스로 scripts/build.ps1 -SkipTests -Package -Msi를 실행한다. 기존 패키징에 포함된 MSI 구조·관리 이미지 추출·파일 해시 검사를 사용하며 test-msi.ps1을 별도로 반복 실행하지 않는다.
4. SourceMode Commit은 깨끗한 Git HEAD를 사용한다. 미커밋 수정본을 배포할 경우 기존 -SourceMode WorkingTree를 명시하고 SourceSnapshot.json과 소스 일치를 확인한다.
5. 완성 ZIP의 실행·스티커 시작 확인은 최초 적용/재시작 확인 흐름에 묶어 한 번 수행한다. MSI 설치·업데이트·제거·재부팅 전체 매트릭스는 추가하지 않는다.
6. 기존과 같은 6종을 artifacts/releases/<빌드시각>/에 생성하고 GitHub Releases v0.2.5로 전달한다: WorkBookmark-0.2.5-win-x64.msi, WorkBookmark-0.2.5-win-x64.zip, Source.zip, SourceSnapshot.json, WorkBookmark-0.2.5-win-x64.validation.json, SHA256SUMS.txt.
7. 릴리스 노트에 기존 스티커 크기와 시작 모드가 최초 1회 바뀜을 명시한다. 이번에 통과한 검사와 재실행하지 않은 독립 검사를 구분한다. MSI 검증 JSON은 UI 검증 결과를 대신하지 않는다.

DB v5를 유지하므로 0.2.3 복귀 시 별도 DB 스키마 복원은 필요하지 않다. 포터블은 이전 전체 폴더로 복귀하고 MSI는 기존 다운그레이드 차단 정책에 따라 새 버전 제거 후 구버전을 설치한다. 초기화된 예전 스티커 크기는 자동 복구 대상으로 보장하지 않는다.
