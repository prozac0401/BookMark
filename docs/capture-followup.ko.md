# 상태 저장 후속 수정 — 0.1.2

대상 저장소: D:\Github_REPOS\BookMark. CSV 웹앱에는 해당 기능이 없어 보고된 기능·단축키가 일치하는 이 저장소에서 수정했습니다. 기존 소스 변경을 보존했습니다.

## 변경과 확인한 원인

- Edge의 설치된 업무 책갈피 확장에는 저장 단축키가 배정되지 않았습니다. 기존 제안 Ctrl+Shift+Y는 Edge 컬렉션 단축키와 겹칩니다. 확장 0.2.2의 신규 제안은 Ctrl+Shift+9이며, 팝업이 실제 배정 상태와 ‘단축키 설정 열기’를 제공합니다. 기존 설치의 사용자 키 배정은 유지됩니다.
- Chrome에는 Ctrl+Shift+Y가 배정되어 있습니다. 이 PC 로그에서 브라우저 저장 커밋 1건은 확인했지만 어떤 브라우저·입력 경로인지는 로그로 구분할 수 없습니다. Chrome 실패의 원인을 Edge 충돌과 같다고 단정하지 않습니다.
- 앱의 브라우저 안내는 특정 키를 단정하지 않고 확장 버튼과 실제 단축키 확인을 안내합니다.
- Word의 ‘읽기만 허용’ 문서 보호는 위치를 읽을 수 있는데도 거절했습니다. 보호를 해제하지 않고 본문 위치를 읽고 선택할 수 있도록 조정했습니다. 일반 읽기 전용과 Office 보호된 보기는 별개입니다.
- 메모장 파일 선택창은 원래 메모장 창을 소유 창으로 지정합니다. 미저장 변경이 있으면 불필요한 파일 선택 전에 저장 필요를 알립니다. 캡처 거절·파일 선택 단계와 실제 앱 버전을 진단 로그에 기록합니다. 문서 내용·경로는 진단 로그에 기록하지 않습니다.

## 사용

브라우저 도구 모음에서 업무 책갈피를 열고 ‘이 페이지 저장’을 누릅니다. 저장 단축키가 미배정이면 ‘단축키 설정 열기’에서 ‘현재 페이지를 WorkBookmark에 저장’에 Ctrl+Shift+9 등 사용 가능한 키를 지정합니다. 기존에 설치한 확장은 새로고침 또는 브라우저 재시작이 필요합니다. 일반 HTTP/HTTPS 페이지와 실행 중인 WorkBookmark 앱이 필요합니다.

메모장은 먼저 문서를 디스크에 저장한 뒤 Ctrl+Alt+B를 누르고 현재 탭의 원본 파일을 선택합니다. 내용·문자 위치가 파일 선택 전후 동일해야 책갈피를 남깁니다. 재개는 파일 열기 요청이며 자동 커서 복원은 아직 제공하지 않습니다.
