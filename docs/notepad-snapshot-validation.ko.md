# 메모장 자동 보관 및 검증 결과 — 0.1.3

2026-09-19. 사용자 요청에 따라 새 메모장을 임의 경로에 먼저 저장하지 않고도 책갈피를 만들고 복원할 수 있도록 변경했습니다. 원본을 저장하거나 덮어쓰지 않습니다. 본문과 선택 범위는 로컬 DB에 보관하며, 복원할 때 앱이 별도 작업 사본을 만듭니다.

## 검증 결과

| 범위 | 묶음 | 최종 통과 검사 | 실제 검증 범위 |
|---|---:|---:|---|
| Core·SQLite·IPC·폼·브라우저 등 | 12 | 266 | 구성요소/대역과 실제 호스트·프로세스·DB 검사를 구분해 엑셀에 기록 |
| 메모장 정책·파일·좌표 | 1 | 28 | 빈 본문, Unicode, 줄바꿈, 긴 선택 좌표, 고유 작업 사본, 제목 정규화 |
| 설치된 메모장 | 1 | 29 | 빈 문서14 + 미저장 한글·이모지·여러 줄15. 본문5,463 UTF-16 문자와 선택5,449–5,463 복원 및 스크롤 확인 |
| 설치된 Word·PowerPoint | 5 | 20 | Word 일반/읽기 전용/편집 제한, PowerPoint 일반/읽기 전용 |
| 합계 | 19 | 343 | 서로 크기가 다른 검사 단위의 합계이며 기존65개 전체 사용자 시나리오의 완전 통과를 의미하지 않음 |

메모장 복원에서 확인한 MSIX 경로 가상화와 파일 로딩 중 일시적 읽기 지연을 수정했습니다. 파일 핸들로 실제 경로를 구하며, 읽기 전용 관측 단계에서만 입력·문서 식별·요청 기한을 확인하며 잠시 기다립니다. 확인된 새 복원본의 본문과 선택 위치가 일치할 때만 성공으로 알립니다. 메모장이 빈 탭을 재사용하거나 상위 창의 제목을 활성 복원 탭 이름으로 바꿀 수 있습니다. 기존의 내용 있는 원본 편집기 본문과 선택은 보존됐습니다.

일반 Word의 최초 캡처는5초, 일반 PowerPoint는3초 기한에서 각각1회 시간 초과했습니다. 문서 초기화 후 각1회 재실행은 통과했습니다. 이 초기 실패2건은 별도 evidence1 파일에 남겼으며, 문서 최초 실행 지연이 해결됐다고 판단하지 않았습니다. 실제 앱의 캡처 기한은3초입니다.

## 추가 전체 흐름 검증

H01 새 미저장 메모장, H02 기존 파일 미저장 변경·여러 탭, H03 Chrome, H04 Edge, H05 탐색기 활성 탭, H06 한국어 IME의 6건은 자동화 대상입니다. 사용자 직접 실행을 필수로 요구하는 목록이 아닙니다.

첫 시도에서는 H01~H03이 실행 도중 차단됐고 H04~H06은 도구 중단으로 시작하지 못했습니다. 이후 재시도는 Windows 제어 도구의 네이티브 연결 실패로 6건 모두 시작 전에 중단됐습니다. 당시 CPU 표본 세 차례는 100%였으며, 자원 여유가 있는 조건의 검증을 완료한 것으로 볼 수 없습니다. 자원 부하와 연결 실패의 인과관계는 확인되지 않았습니다. 6건 모두 제품 성공·실패 판정은 보류합니다.

## 설치와 보존

앞선 설치 작업에서 두 설치 위치의 0.1.3 핵심 파일 해시와 배포본 일치를 확인했습니다. DB·설정 백업과 스키마 4 이관도 검증했습니다. Codex의 경로 가상화 환경에서 확인한 DB와 일반 실행 앱의 DB를 구분해야 합니다. 일반 실행 앱의 읽기 전용 비교에서는 기존 기록 4건이 동일했으며, 이 결과는 당시 관측 범위에 해당합니다.

메모장 실제 앱 검사 증거는 docs/evidence/notepad-snapshot-*-final-2026-09-19.json입니다. 현재 배포 범위와 남은 조건은 [0.1.3-preview.1 릴리스 노트](release-notes-v0.1.3-preview.1.md)에 정리합니다.
